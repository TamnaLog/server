# 홈 조회 비즈니스 룰

## 1. 기본 처리

홈 조회 API는 사용자가 홈 화면에 진입하거나 홈을 새로고침할 때 필요한 데이터를 한 번에 반환한다.

반환 대상:

- 추천 미션 목록
- 진행 중인 미션 목록
- 쌓인 방명록 개수
- 사용자에게 배정된 AR 캐릭터 이미지 URL

현재 로그인 기능은 구현되어 있지 않으므로 API를 호출하는 사용자는 항상 `id=1`로 처리한다.

## 2. 추천 미션

추천 미션 선정 로직은 API 함수나 service 함수 안에 직접 작성하지 않는다.

별도 모듈로 분리해서 구현한다.

예시 위치:

```text
app/home/mission_recommender.py
```

현재는 추천 기준이 확정되지 않았으므로 DB에 존재하는 미션 중 랜덤으로 선택해서 반환한다.

추후 추천 기준이 확정되면 해당 모듈 내부의 랜덤 로직을 실제 추천 로직으로 교체한다.

## 3. 거리 및 예상 소요 시간

요청 query의 `latitude`, `longitude`를 사용자 기준 위치로 사용한다.

미션에 장소가 있으면 사용자 위치와 미션 장소 좌표 사이의 직선거리를 계산해 `distanceMeter`로 반환한다.

예상 소요 시간은 직선거리를 기준으로 대략 계산해 `durationMinutes`로 반환한다.

계산 기준은 100m를 1분 20초에 걷는 것으로 가정한다.

즉, 직선거리에 비례해 예상 소요 시간을 계산한다.

미션에 장소가 없으면 아래 값은 `null`로 반환한다.

- `locationTitle`
- `location`
- `distanceMeter`
- `durationMinutes`

## 4. 진행 중인 미션

진행 중인 미션은 미션 유형별 진행도 테이블에서 `IN_PROGRESS` 상태인 데이터를 조회한다.

문화 미션과 보물찾기 미션은 진행도 테이블의 `user_id`로 현재 사용자의 진행 중 미션을 찾는다.

협동 미션은 진행도 테이블에 `user_id`가 직접 없으므로 참여자와 역할 진행도를 통해 현재 사용자가 참여 중인 진행도를 찾는다.

## 5. 단계 정보

`totalStep`과 `currentStep`은 프론트에서 화면 진행 상태를 관리하기 위한 값이다.

문화 미션은 퀴즈 진행도를 단계 정보로 사용한다.

- `totalStep`: `CULTURE_MISSION.quiz_total_count`
- `currentStep`: `CULTURE_MISSION_PROGRESS.current_quiz_index`

보물찾기 미션과 협동 미션은 공통 미션 단계 정보를 사용한다.

- `totalStep`: `MISSION.step_detail`의 항목 개수
- `currentStep`: 각 미션 진행도 테이블의 `current_step`

백엔드는 명세에 필요한 값을 반환하되, 프론트 화면 단계 정책을 추가로 판단하지 않는다.

## 6. 방명록 개수

`guestbookCount`는 현재 사용자가 작성한 방명록 수가 아니라 서비스에 쌓인 방명록 수를 의미한다.

방명록 개수 계산 로직은 API 함수나 service 함수 안에 직접 작성하지 않는다.

별도 함수 또는 모듈로 분리해서 구현한다.

예시 위치:

```text
app/home/guestbook_counter.py
```

현재는 기획이 확정되지 않았으므로 일반 방명록과 길바닥 방명록의 전체 개수를 합산해서 반환한다.

삭제된 방명록은 개수에서 제외한다.

추후 집계 기준이 확정되면 해당 모듈 내부의 전체 개수 합산 로직을 실제 집계 로직으로 교체한다.

## 7. 캐릭터 이미지

사용자에게 배정된 AR 캐릭터가 있으면 해당 캐릭터의 이미지 URL을 `characterImgUrl`로 반환한다.

사용자에게 배정된 AR 캐릭터가 없으면 `characterImgUrl`은 `null`로 반환한다.

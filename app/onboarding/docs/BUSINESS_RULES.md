# 온보딩 비즈니스 룰

## 1. 기본 처리

사용자 온보딩 정보 저장 API는 사용자가 선택한 온보딩 값을 저장한다.

저장 대상:

- 여행 기대 항목
- 주 이동 수단
- 자투리 시간 여행 방식

현재 로그인 기능은 구현되어 있지 않으므로 API를 호출하는 사용자는 항상 `id=1`로 처리한다.

## 2. 여행 스타일 및 AR 캐릭터 배정

원래는 사용자 온보딩 결과에 따라 정해진 여행 스타일과 AR 캐릭터를 배정해야 한다.

다만 현재는 기획과 매칭 기준이 확정되지 않았으므로 임시로 랜덤 배정한다.

랜덤 배정 대상:

- DB에 존재하는 여행 스타일
- DB에 존재하는 AR 캐릭터

배정된 여행 스타일과 AR 캐릭터는 사용자 정보에 저장하고, API 응답에도 포함한다.

## 3. 배정 로직 분리

여행 스타일과 AR 캐릭터를 배정하는 로직은 API 함수나 service 함수 안에 직접 작성하지 않는다.

별도 모듈로 분리해서 구현한다.

예시 위치:

```text
app/onboarding/onboarding_matcher.py
```

현재 구현은 랜덤 배정만 담당한다.

추후 온보딩 결과 기반 매칭 기준이 확정되면 해당 모듈 내부의 랜덤 로직을 실제 매칭 로직으로 교체한다.
